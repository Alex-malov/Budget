# Budget v1.1.0 — план релиза

Статус: в локальной разработке. Сборка, тег, публикация и развёртывание требуют отдельного подтверждения владельца продукта.

## Задачи для GitHub Project «Budget»

### BUD-01. Базовый процесс разработки и релизов

- Зафиксировать `v1.0.0` как базовую версию исходного кода.
- Вести доработки в ветках `codex/feature/*` и `codex/fix/*`.
- Фиксировать в релизном реестре состав задач, проверки, commit SHA, контрольную сумму сборки и условия отката.
- Не выполнять push, tag, публикацию артефакта и деплой без отдельного подтверждения.

### BUD-02. Общие подписи и месяцы

- Полные названия месяцев использовать в фильтрах и иных широких областях интерфейса; сокращения — только в узких таблицах.
- Убрать подпись с названием исходного Excel-файла и датой со всех страниц.
- Убрать блок «Источник данных» со всех страниц.

### BUD-03. НСИ «Прочий подряд»

- Переименовать поле и колонку «Наименование» в «Статья/Подрядчик».
- Добавить к форме блок НДС по годам и месяцам по аналогии со справочником «Поставщики».
- В реестре показывать «НДС: Да», если заполнено хотя бы одно месячное значение, иначе «Нет».
- Использовать категории: «Основные», «Косвенные», «Прочие» с согласованными подсказками.
- Для НДС разрешить только ставки `0%`, `5%`, `7%`, `10%`, `22%`; первая выбранная ставка заполняет следующие месяцы года, сохраняя возможность их изменения.

### BUD-04. Раздел «Прочий подряд»

- Разместить пункт после «Проектные расходы (себест)».
- Реестр расходов на подряд, не связанный с привлечением ресурсов, с фильтрами «Проект» и «Год».
- Для каждого года отображать свёрнутый блок месяцев и последовательные блоки «План» и «Факт».
- В каждом блоке показывать «Стоимость» (`Сумма + НДС`), «Сумма» и «НДС» (`Сумма × ставка НДС` объекта НСИ для месяца).
- План и факт сохранять в локальном хранилище `other-subcontract-overrides.json`; серверный API должен отдавать рассчитанные помесячные значения, чтобы реестр не зависел от расчётов браузера.
- В реестре после порядкового номера отображать проект; помесячные ячейки «Сумма» плана и факта доступны для изменения двойным щелчком. Метрики используют тот же фильтр проекта и года, что и реестр.

## Проверки перед релизным кандидатом

1. Автоматические тесты API и проверка синтаксиса.
2. Локальный сценарий создания, изменения, архивирования и просмотра НСИ.
3. Проверка расчётов плана/факта, НДС и свёрнутых годов/месяцев.
4. Проверка отсутствия исходного файла и источника данных на страницах.
5. Ручная проверка локальной Windows-сборки.

## Ход реализации

- BUD-01: локальная ветка `codex/feature/v1-1-other-subcontract` и реестр релиза подготовлены; публикация и деплой не выполнялись.
- BUD-02: выполнено — в фильтрах применены полные названия месяцев; подпись исходного файла и блок «Источник данных» удалены из интерфейса.
- BUD-03: выполнено — НСИ «Прочий подряд» использует поле «Статья/Подрядчик», категории «Основные», «Косвенные», «Прочие», помесячный НДС и признак его наличия в реестре. НДС выбирается только из ставок 0%, 5%, 7%, 10% и 22%; первая выбранная ставка переносится на следующие месяцы года.
- BUD-04: выполнено в локальном релиз-кандидате — добавлен отдельный раздел с проектно-годовым срезом, свёрнутыми годовыми блоками, помесячным раскрытием и расчётом стоимости/НДС для плана и факта. План и факт разделены на самостоятельные блоки; значения, сохранённые через форму, хранятся в `other-subcontract-overrides.json` и повторно загружаются в реестр вместе с серверным расчётом НДС и стоимости. При первом открытии раздела выбран текущий год. Колонка «Проект» расположена после номера; помесячные «Суммы» плана и факта выделены тоном и редактируются двойным щелчком. Повреждённое хранилище с несколькими JSON-документами теперь автоматически восстанавливается из первой корректной модели, а исходный файл сохраняется в `data/backups`.

Проверено локально 11.08.2026: синтаксис клиентского и серверного кода, 6 автоматических тестов API, включая валидацию недопустимой ставки НДС, сохранение плана/факта прочего подряда и восстановление повреждённого JSON-хранилища. Сборка, тег и публикация артефакта не выполнялись.
