# BUD-10, BUD-12, BUD-13 — дизайн и внутренняя приёмка версии 1.4.0

Дата: 25.08.2026. База: чистая версия `1.2.0`; ветка реализации — `codex/feature/v1-4-budget-financial`.

## Объём и инварианты

Реализованы требования BUD-10, BUD-12 и BUD-13 без изменения исходных операционных записей. Поток данных остаётся односторонним:

```text
НСИ → Команда / Суммы и часы штат / Суммы и часы подряд / Прочий подряд
    → расчётный слой по месяцам → Доходы, оплаты и Финансовый план-факт
```

Аналитические страницы не создают копий НСИ и не редактируют начисления. События «Доходы» и «Оплаты» — самостоятельные операционные записи с проектным кодом, сценарием, месяцем и снимком НДС. НИС «Финансовые ставки» хранит налог на прибыль и овердрафт глобально, ставку дирекции — по проекту и периоду. Пересекающиеся периоды одной ставки не сохраняются; удалённая ставка архивируется для воспроизводимости истории.

## Матрица метрик, формул и источников

| Метрика в UI | Формула | Источник | Пояснение |
| --- | --- | --- | --- |
| Поступления с НДС | `Σ gross` | События «Доходы» | Кнопка `?` в строке метрики. |
| НДС поступлений | `Σ gross × rate / (100 + rate)` | Снимок НДС в доходе | Ставка не изменяет исторический документ. |
| Прочий подряд с НДС | `Σ(сумма + сумма × НДС)` | «Прочий подряд» + НСИ НДС | Раскрытие источника и заголовочная подсказка. |
| Ресурсный подряд с НДС | `Σ((себест. + привл.) × часы × (1 + НДС))` | Команда / факт подрядчика + карточка ресурса + поставщик | Пояснение формулы и строка источника. |
| Себестоимость штата | `Σ(ставка × часы)` | Команда / «Суммы и часы штат» + карточка ресурса | НДС к штату не применяется. |
| Расходы с НДС | `прочий подряд + ресурсный подряд + себестоимость штата` | Расчётный слой | Кнопка `?`. |
| НДС всего | `НДС поступлений − НДС расходов` | Расчётный слой | Кнопка `?`. |
| Чистая прибыль | `прибыль до налога − налог` | Расчётный слой + НСИ ставок | При отсутствии обязательной ставки — «Не рассчитано». |
| Инвестирование | `(поступления с НДС − прочий подряд с НДС) × 10%` | Расчётный слой | Кнопка `?`. |
| Дирекция | `(поступления − прочий подряд − инвестирование) × ставка дирекции` | Расчётный слой + НСИ ставок | Требуется ставка проекта и периода. |
| Распределение ЛТ | `Σ(привлечение штатного ресурса × часы)` | Карточка ресурса + часы штата | Не входит в расходы. |
| ДКС | `чистая прибыль − инвестирование − дирекция − ЛТ − овердрафт` | Расчётный слой | Кнопка `?`. |
| Денежный поток | `поступления − оплаты − себестоимость штата` | Доходы, оплаты, часы штата | Начисления подрядчика не заменяют оплату. |
| Овердрафт | `max(0; накопленный ДП)`; проценты — по средней задолженности | Расчётный слой + ставка овердрафта | Тело долга не вычитается из прибыли и ДКС. |

## Контрольный расчёт BUD-13

Для контрольных значений из BUD-13 реализован единый, тестируемый контракт [`financial-formulas.js`](../../public/financial-formulas.js). Автотест использует: поступления 6 100, НДС 1 100, прочий подряд 610, ресурсный подряд 1 464, штат 800, ЛТ 200, НДС расходов 374, налог 5%, дирекция 5%, овердрафт 0.

| Результат | Значение |
| --- | ---: |
| Расходы с НДС | 2 874 |
| Прибыль с НДС | 3 226 |
| НДС всего | 726 |
| Прибыль до налога | 2 500 |
| Налог / чистая прибыль | 125 / 2 375 |
| Инвестирование / дирекция | 549 / 247,05 |
| ДКС | 1 378,95 |
| Рентабельность / налоговая нагрузка | 47,5% / 14,0% (13,95% до округления) |

Для сценария денежного потока из BUD-13 предусмотрен помесячный расчёт накопленного остатка, потребности и максимума овердрафта; начисления подрядчиков попадают в сверку, но не подменяют оплату.

## Доказательства проверки

1. Синтаксическая проверка `server.js`, `financial.js`, `financial-formulas.js` — пройдена.
2. `node --test test/server.test.js`: 8 из 8 тестов, в том числе контроль BUD-13, код проекта после операции, конфликт периодов ставок, независимые доходы и оплаты.
3. Локальная UI-проверка на desktop и ширине 390 px: загрузка завершена, доступна навигация из восьми разделов и горизонтальная прокрутка таблиц; на экранах проверены форма дохода, форма оплаты, форма ставки, план-факт, состав проектных расходов и модальное пояснение формулы.
4. Дефекты Blocker / Critical / Major: не обнаружены. Автоматизированная проверка не записывала тестовые данные в рабочую БД.

## Вердикт BUD-13

**PASS для внутренней приёмки кандидата 1.4.0.** Все проверяемые требования BUD-10 и BUD-12 реализованы и подтверждены тестами выше. Пользовательское согласование выпуска, публикация тега и развёртывание остаются отдельными действиями владельца продукта.
