# Модель данных и правила контроля

## Логическая модель

```text
project 1 ──── * planning_entry
project 1 ──── * resource_assignment * ──── 1 employee
role    1 ──── * employee
role    1 ──── * rate_version
project 1 ──── * contract
planning_entry * ──── 0..1 actual_import
```

`planning_entry` — главная факт-таблица для MVP. Её уникальный ключ: `(project_id, period, scenario)`. Период хранится как `YYYY-MM`, сценарий — только из справочника `План`, `Прогноз`, `Факт`.

## Таблицы MVP

### `project`

| Поле | Назначение |
| --- | --- |
| `id`, `code`, `name` | Идентификатор и видимое имя проекта |
| `customer`, `manager`, `status` | Фильтры и владельцы |
| `contract_start`, `contract_end` | Контроль периода договора |

### `planning_entry`

| Поле | Вводится | Правило |
| --- | --- | --- |
| `project_id`, `period`, `scenario` | Да | Уникальны вместе |
| `revenue` | Да | ≥ 0; без НДС, единый формат рубля |
| `payroll_cost` | Да | ≥ 0 |
| `subcontract_cost` | Да | ≥ 0 |
| `other_cost` | Да | ≥ 0 |
| `planned_hours` | Да | ≥ 0 |
| `capacity_hours` | Да | ≥ 0; если плановые часы > 0, то > 0 |
| `updated_at` | Нет | Заполняется системой |

## Производные показатели

```text
cost          = payroll_cost + subcontract_cost + other_cost
margin        = revenue - cost
margin_rate   = margin / revenue             (если revenue > 0)
utilization   = planned_hours / capacity_hours (если capacity_hours > 0)
risk          = margin < 0 OR utilization > 1
```

Показатели не хранятся как ручные значения. Они рассчитываются при чтении, чтобы после исправления первичных данных не возникало рассинхронизации.

## Контроли при вводе

1. Нельзя записать отрицательную сумму или часы.
2. При наличии плановых часов нельзя оставить нулевую ёмкость.
3. Повторный ввод той же комбинации проект–месяц–сценарий обновляет запись, а не создаёт дубликат.
4. Отрицательная маржа и загрузка выше 100% не запрещают сохранение: это управленческие сигналы, а не ошибка ввода.
5. Для промышленной версии добавить закрытие периода, статус согласования, автора/утвердившего и неизменяемый аудит.

## Расширение до детальных ресурсов

Если нужен контроль на уровне сотрудников, добавляется `resource_assignment`: сотрудник, проект, роль, месяц, плановые часы, ставка/версия ставки. Из неё суммируются часы `planning_entry`; финансовые значения по ставке хранятся с указанием версии методики. Это исключает сегодняшние внешние ссылки между листами Excel и делает пересчёт воспроизводимым.
